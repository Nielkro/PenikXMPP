# DinoX Flatpak third-party inventory

This file records the components selected by `im.dinox.dinox.json`. It is an
inventory, not a legal opinion or a claim that merely listing a component is
sufficient for every distribution jurisdiction. The pinned source archives and
the license files shipped in the Flatpak remain the authoritative material.

## Installed license material

- DinoX: `/app/share/licenses/dinox/dinox/{LICENSE,NOTICE,AUTHORS}`
- Google/libwebrtc runtime:
  `/app/share/licenses/dinox/google-libwebrtc/{LICENSE,LICENSE.md,PATENTS,manifest.json,FFMPEG-LICENSE,LIBVA-LICENSE,FFMPEG-VP8-VAAPI.json,NVIDIA-CODEC-HEADERS-LICENSE,WEBRTC-CODECS.json,WEBRTC-GN-ARGS.gn}`
- Offline Vision worker and models:
  `/app/lib/dinox/dinox-vision-licenses/{PROJECT_LICENSE,MODEL_AND_CUSTOM_OP_LICENSE,dependencies/<component>/...}`;
  the original texts and compiled-source attribution are hash-bound in
  `/app/lib/dinox/dinox-vision-runtime-manifest.json`.
- Bundled application modules:
  `/app/share/licenses/dinox/third-party/<component>/...`; license and notice
  files are copied recursively from each pinned source archive while preserving
  their relative paths (including Lyrebird's vendored Go dependency notices).
- libomemo-c's exact `README.md` is additionally staged at
  `/app/share/licenses/dinox/third-party/libomemo-c/README.md` and hash-gated;
  it contains the upstream App Store additional permission named below.
- This inventory: `/app/share/licenses/dinox/THIRD_PARTY_NOTICES.md`

`LICENSE.md` is generated by the Google/libwebrtc license generator for the
exact `//:webrtc` dependency graph. `FFMPEG-VP8-VAAPI.json` records the exact
minimal FFmpeg/libva/NVIDIA-header source inputs shipped as private dynamic
hardware codec libraries in the Linux runtime. NVIDIA headers are MIT licensed;
the proprietary driver is supplied by the host or Flatpak graphics extension. M152 also links Chromium's separate FFmpeg
software decoder and OpenH264 software encoder for live calls. Their notices
are included in `LICENSE.md`; `WEBRTC-CODECS.json` records the exact codec-source
archive and hash, and `WEBRTC-GN-ARGS.gn` records the build arguments. The source
archives are installed below `/app/share/licenses/dinox/google-libwebrtc/sources/`,
including `webrtc-m152-codec-sources-6f37672d3584-sha256-2b17c14cc13b.tar.gz`
(SHA-256 `2b17c14cc13b4b661c4a2be9b25c26240c97cec4a1c938196ed81dc9fd24278c`).

## Prebuilt Google/libwebrtc runtime

The Flatpak consumes
`https://git.dinox.im/dinoxim/dinox/releases/download/vendor-deps/libwebrtc-m152-linux-x86_64-runtime-abi40-ipc10-sha256-2479cdb9ab7e.tar.gz`,
pinned with SHA-256
`2479cdb9ab7eace826e28d519a9dd33478329e34c303ed716c196005d9cec46f`.
Its `manifest.json` records WebRTC milestone 152, the exact upstream revision,
the DinoX wrapper ABI, and the private VA-API/NVIDIA hardware codec metadata. Its
ten WebRTC notice files are listed above. Wrapper ABI 40, control IPC 10 and
video ring 6 include a separate offline Vision worker and two pinned models:
`selfie_segmenter_landscape-v1.tflite` and `blaze_face_short_range-v1.tflite`.
The WebRTC M152 SDK and codec sources remain unchanged. TensorFlow Lite,
XNNPACK and the other compiled inference dependencies keep their original
license texts in the separate Vision license tree; they are not covered merely
by the existing WebRTC `LICENSE.md`.

The matching desktop inference source recipe is
`https://git.dinox.im/dinoxim/dinox/releases/download/vendor-deps/dinox-vision-desktop-sources-46b1d2639244-f36320e8.tar.gz`,
SHA-256 `939119005e1a6f6fb62367ec8d0e097daba4161dd702788529003e1573cdcee6`.
It preserves the actual inference sources, models, original model/custom-op
license and cached-dependency build pins. This source companion is not a
second runtime download during normal installation or calls.

## Components supplied by the Flatpak runtime

DinoX targets `org.gnome.Platform` 50, based on the Freedesktop 25.08 runtime.
The Flatpak application module uses runtime components for chat media-message
writing and playback. These are separate from the prebuilt call runtime above:

- Linux audio/video messages use the runtime `/usr/bin/ffmpeg` command for
  AAC/M4A and H.264/MP4 writing and muxing.
- Media-message H.264 encoding is provided by `libx264` from
  `org.freedesktop.Platform.codecs-extra` 25.08-extra. That extension is
  declared by the GNOME runtime as an automatically downloaded runtime
  extension; the installed-package gate verifies its actual availability.
- GStreamer from the GNOME/Freedesktop runtime is used only for playback,
  demuxing, decoding, metadata extraction, and the appsink bridge to the
  Google/libwebrtc speaker path. MQTT critical-alert playback additionally
  uses the runtime audio-sink plugins; ordinary Linux notification sounds use
  libcanberra.
- Live call capture, codecs, RTP, ICE, STUN, and TURN are handled by the
  Google/libwebrtc runtime, not by a GStreamer RTP/capture module.

The exact licenses and build configuration for runtime-supplied components are
part of the installed GNOME/Freedesktop runtime and codecs-extra metadata, not
of the DinoX application module source list.

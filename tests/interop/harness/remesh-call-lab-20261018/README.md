# Remesh call-lab follow-up sources, October 18, 2026

The Android APK server-build and all pq-* sources were relocated byte-identically to the
[Monocles retained fixture](https://git.dinox.im/dinoxim/monocles-chat/src/commit/a4980b9f43bc6288cc0cfc0abcf188623f1949ea/tools/interop/retained_fixture/README.md).
The inventory below is historical; native/mixed sources remain here. Frozen
paths and pins are unchanged, so this snapshot is not standalone.

This source-only snapshot preserves selected follow-up scripts under the user's
instruction to version private test code while excluding logs and private data.
It records source provenance, not a live interoperability result or a portable
test suite. No application build or test target registers these helpers.

| Directory | Scope |
| --- | --- |

`source-snapshot.json` records original and archived digests and byte sizes.
Only final newlines may be normalized; Python/source-fragment ASTs are unchanged.
Original sources and private operating closures remain intact. Public fixture
JIDs, device identifiers, artifact fingerprints and fixed lab paths are source
constants. Credential and signing-key contents, password files, profiles, APKs,
screenshots, logs, results and operational admissions are excluded.

Several modules validate private inputs on import. Read them as source; do not
import an operating module or run `--help` for inspection. The complete private
closure, actual resource/owner checks and fresh operating admissions are required.
Python assertions must remain enabled. The original pre-derivation checker
`product-qualification/check_source_only.py` is not a new artifact or runtime pass.

Mixed three-client video uses legacy OMEMO. DinoX's PQ path remains disabled.
Media counters, normal UI actions and device/fingerprint authentication require
separate evidence. The native single-fingerprint observer does not certify every
fingerprint node of an audio/video call. This snapshot does not turn a failed or
uncertain historical operation into a pass.

The PQ sibling uses three Monocles clients and the existing normal JOIN/REJOIN
case. Only the original, validated and published stop request can finish reading
its response after normal instrumentation exit. Other operations retain their
live-bridge requirement. Its preparation checker is source inspection, not new
live-media, authentication or capacity evidence. Unchanged dependencies remain
in the earlier interop snapshots or in the omitted private laboratory closure.

The popup successor binds a focused attached application subwindow to its real
WindowManager parent, process, account application, frame, transform and one
responsive input channel. Unknown or contradictory owners remain blocked. Its
checker reads ignored original local fixtures and has no live UI authority.

The PQ operators preserve only source. Eleven copies were rebased inline from
private parent operators; no separate operator generator is claimed. The launcher
uses the existing case and three actual bounded join/rejoin checkpoints once.
Private admissions, dynamic identities and current QR evidence remain required.
The PQ case starts a room call; it does not exercise conversion of an ongoing
one-to-one PQ call into a three-participant conference.

The guarded-exit postcheck records stopped processes separately from unconfirmed
app-configuration restoration, missing stop acknowledgements and an unproved
ordered emulator shutdown. Its presence does not convert these cases to passes.

The offline lock successor allows the read-only resource inventories to share a
lock while SDK, lifecycle and UI operations retain exclusive access. Existing
process identities and scopes, the five-second acquisition limit and the existing
SDK, touch and Stop deadlines remain in place. Its synthetic kernel-lock tests do not reconstruct the unknown
historical lock holder or explain the later emulator exits.

The offline capture successor omits original own-account screenshots and mixed
raw bundles, sanitizes derived XML in memory and keeps unsafe input hash-only.
The bound own-QR dialog uses the existing decoder with its original PNG only in
RAM; no full image, raw envelope or crop is archived. Both offline successors are
source evidence. The historical PQ attempt stopped before OwnQR verification or
audio-case submission and remains partial; these copies do not establish a live
QR, authentication or media pass.

The combined directory adds only the pure component composer and the initial
Nora capture helper. That barrier requires an original public PNG and cannot
claim success from a derived private-account view. The remaining operating
outputs, private grants and live results are deliberately omitted. These two
source copies do not certify that any later PQ attempt completed.


The capture-file diagnostics add fixed error enums for existence, regular-file
status, readability, counting and size validation after the unchanged UIA/PNG
waits. They retain the original size bounds and withhold raw output and exception
text. This source-only diagnostic was not run on a guest; the historical capture
Exit1 cause remains unproven.

The ordered-stop successor records an exactly bound foreign own emulator in its
existing normal shutdown window as a separate, not-terminal resource transition.
PID/startticks, parent, process group and both child/controller cgroups remain
bound before and after inspection. Live/control and final settlement gates are
unchanged. Historical Z snapshots do not prove surviving threads or a particular
pidfd failure; the real offline kernel regression demonstrates a possible longer
transition. No new operating closure, guest run or PQ success is established by
these source copies.
